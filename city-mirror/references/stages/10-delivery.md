# 阶段十：交付（city-mirror 阶段文件）

> **入口**：定稿正文＋双审通过
> **出口**：详细版／发布版＋配图（或有据留空）＋HTML 预排版＋（可选）草稿箱推送、PDF＋质检清单勾选结果
> **本阶段不管什么**：只管交付形态，不改正文——要改正文回⑧⑨，按改稿复检的分级重跑。
> **本阶段红线**：出图只走脚本｜缺口画法｜绝对值与增速不可互推｜历史值会被修订｜发布版必留五类口径说明｜搜图结果表｜推送前须用户确认
> **用户拍板点**：MD 定稿确认；推送草稿箱前确认
>
> 本文件只管本阶段怎么做。跨阶段的约定见 SKILL.md「阶段路由与接口总表」；三层制与贯穿全程的骨干规则同样在 SKILL.md，冲突时以其红线为准。

---

## 一、这一步做什么

把定稿变成能发的东西。**默认交付路径：成稿 Markdown → 用户确认内容 → 生成公众号 HTML 预排版。**

只管交付形态，不改正文——要改正文回⑧⑨，按改稿复检的分级重跑。

## 二、怎么做

### 第一步：MD 定稿确认

先交 Markdown 全文（带来源与口径说明），用户确认后再配图与排版；

### 第二步：出双版本（详细版／发布版）

正文完全相同，只有文末来源区与正文引用标记不同。**详细版是母本，发布版由它压缩生成，不得独立撰写**——否则"每个关键数据有出处"这条纪律会在压缩中悄悄丢失：
  - **详细版**（`文章名_详细版.md`，供作者自查与备查）：保留正文〔n〕标记、逐条编号的「信息来源」（媒体／日期／URL）、完整「数据口径说明」。⑧第二轮、⑨双审、质检清单**一律以详细版为准**；
  - **发布版**（`文章名.md`，实际推送的版本）：**去掉正文〔n〕标记**（标记失去对应的编号列表就成了孤儿），文末改为一段**「信息来源」短文**——按来源类别归并，不逐条不编号，通常 3-5 句、150 字以内。写法：把 28 条压成"数据来自 X、Y；项目信息据 Z 等公开报道整理"；
  - **发布版必须保留的口径说明（红线，只保留"不说会让读者读错"的那几条）**：①单方叙述（项目方通稿、企业自述）；②效果图非实景；③非官方口径的排名与称号（如"第一商圈"）；④同一指标两口径并存时的说明；⑤历史值经修订的说明。**纯技术性口径**（如"含餐饮非纯零售额""统计时点为年末"）并入短文或略去；
  - **判定标准**：删掉这条，读者会不会把某件事读成另一件事？会——留；不会——删。发布版的目标不是省字数，是让声明**被读完**（列 8 条没人看，留 3 条才有人读）；
  - 两版同时交付，用户选发哪版；推送草稿箱默认用发布版。

### 第三步：配图

分两类——数据图表（自动生成）和图片配图（自动搜图，含实景图与效果图两种，性质不同见下），逐节扫描成稿决定是否配图、配哪类：

#### A. 数据图表（脚本 `scripts/gen_chart.py`）

**只判两件事，参数与红线细则见脚本头注。**

1. **价值门槛**：只在图表比文字更直观时才出图——能让读者一眼看出趋势、差距或结构的，出；用文字一句话就能说清的（如仅两项对比），不出。不设篇数硬限，该出就出、不该出不凑；
2. **选图信号**：时间序列（同一指标跨 ≥3 个时间点）→ `line`／跨对象对比（同一指标 ≥3 个对象）→ `bar`、`barh`／多维结构占比（≥3 个组成部分）→ `barh`／政策沿革与项目历程（≥3 个时点各有一件事）→ `timeline`。

**红线四条（细则在脚本头注，此处只作提示）**：

- **出图只走 `gen_chart.py`，不许手写 matplotlib 代码**。版式约束（宽度、字号、标题换行、注脚位置与长度、配色）全在脚本里，绕开一次就全部失效。脚本没有的图型调 `gzh-chart` skill（可选，不装不影响上面四种）；两者都没有的，**不出图，或先把图型补进 `gen_chart.py` 再出**——不接受"这次先手写一张"。（实战判例：跨平台调用时模型自行手写出图代码，一次出现标题堆叠、注脚冗长、时间轴按时间比例排布留大片空白三个毛病，全部源于绕开了版式收尾。）
- 数据只出自可写事实清单，不为出图编造；
- 缺口不许实线直连，用 `gaps=` 画虚线并标注；
- 绝对值与增速不可互推、历史值会被修订（口径终核在⑦，出图时复查一遍）。

**图上注脚只写「数据来源：X、Y」**，上限 48 全角字，脚本超限报错。换算方式、统计范围、不同对象的口径差异——这些是**口径不是来源**，归正文的「数据口径说明」（发布版必留五类之一）。图上塞不下不是版式问题，是塞错了地方。

数据不全时，脚本头注里有补全的渠道阶梯与预算。

#### B. 图片配图（**参数见 `references/imaging-spec.md`**）

**先分清实景图与效果图**——前者是事实记录，后者是营销物料，图注必须标"非实景"。两者性质不同，不许混称。

**来源只许两个渠道**：① 官方素材（政府／官方媒体 > 项目方官网官微），**取图前必须查页面版权声明**，声明禁止下载即不可用；② 开放版权图库，**涉具体地点一律不用**。自媒体转载、带第三方水印、社交媒体用户照片——禁止。

**流程（强制举证，不接受"计划"代替"执行"）**：逐节判断是否配图 → 定关键词与渠道 → 搜索筛选 → **查验发布方与版权声明** → 下载 → 插入 MD。

**必须产出「搜图结果表」**，每个配图位一行：

```
位置｜渠道｜检索词｜候选数｜最大候选尺寸｜结果（选中／留空+原因）
```

**只写"计划配 XX 图"而无此表＝该步未执行。**（判例：太原古县城一文，B 段只列了"节1 可配全景图→走渠道①"的计划便跳过，且在质检清单里用 A 段的判定冒充 B 段通过，等于交了裸 ✅。**A 段判定与 B 段执行是两件事，各自出证据，不得互相顶替。**）

**配不到就留空**：找不到合规来源时，不降格用禁止来源，也不静默略过——预排版中保留空位并注明「搜图结果：未找到合规来源／主动放弃」+ 一句理由（查了哪些渠道、为什么不用），交用户决定是否自行补拍。（实战：佛光寺一文两个官方渠道均因版权声明禁止下载而全部留空。）

分辨率门槛、比例、画质、署名格式、文件命名、搜索预算——见 `references/imaging-spec.md`。

产出的图表和图片均存入工作目录，成稿 MD 中标注插入位置；

### 第四步：生成 HTML 预排版

公众号版式（677px 内容宽、16px 正文、声明块、小标题、〔n〕引用编号、小号灰字来源区），图表与图片插入对应位置，预留表格位（附排版建议、与正文去重）；生成后用 Chrome 截图自查渲染效果；

### 第五步：推送草稿箱（可选，需用户确认）

HTML 预排版自查通过后，用自带脚本 `scripts/push_to_wechat.py` 一键推送到公众号草稿箱（用法、凭据配置、前置条件见脚本头注）：
  - **推送前必须向用户确认**——推送是外发动作，即使进的是草稿箱也需用户点头；确认时报出标题、封面图、图片张数；
  - **凭据不进仓库**：AppID/AppSecret 存 `~/.config/city-mirror/wechat.json` 或环境变量，脚本从本地读取，skill 仓库可公开发布；
  - **前置条件**：公众号须为已认证服务号/订阅号（个人订阅号无此 API 权限）；服务器出口 IP 须加入公众号后台白名单（否则报 40164）；
  - **先 `--dry-run`**：只上传图片、生成转换结果，不推送草稿，用于确认图片链路与正文转换无误；确认后再正式推送；
  - **渲染差异预期**：微信强制系统字体、过滤 `<style>` 标签（故预排版必须全 inline style）、图片宽度自适应——差异很小，推送后在后台用手机预览确认一次；
  - 脚本只推到草稿箱，不做群发——发布动作始终由用户在后台手动完成。

### 第六步：转 PDF（可选）

需要存档或打印审阅时，用自带脚本 `scripts/md_to_pdf.py` 转换（用法、依赖与脚本特性见脚本头注；生成后用 pdftoppm 抽查无乱码、长 URL 无溢出）。

## 三、预算

- **数据图表**：**不设篇数硬限**，该出就出、不该出不凑——门槛是"图表比文字更直观"，不是数量；
- **图片配图**：搜索预算见 `references/imaging-spec.md`（每篇 ≤10 次）；
- **发布版「信息来源」短文**：通常 3-5 句、**150 字以内**；
- **图上注脚**：上限 **48 全角字**，脚本超限报错。

## 四、产出

- **详细版**（`文章名_详细版.md`）＋**发布版**（`文章名.md`），两版同时交付，用户选发哪版；
- **数据图表**（`gen_chart.py` 直出）与**图片配图**，均存入工作目录，成稿 MD 中标注插入位置；
- **搜图结果表**：每个配图位一行（位置｜渠道｜检索词｜候选数｜最大候选尺寸｜结果）；
- **HTML 预排版**（全 inline style）；
- **质检清单勾选结果**（见「六、质检清单」），随调研底稿落盘；
- 可选：草稿箱推送、PDF。

## 五、回退

- **用户在 MD 定稿确认时提出内容修改** → 回⑧⑨，按改稿复检分级（结构性／段落级／字句微调）重跑，**不在本阶段就地改**；
- **配图配不到合规来源** → 不降格用禁止来源，也不回退，**保留空位并注明原因**，交用户决定是否自行补拍；
- **质检清单有项不过** → 退回该项对应的阶段，不带着不过的项交付。

## 六、完成标准

双版本齐（发布版由详细版压缩生成，非独立撰写）；配图 A 段有判定、B 段有「搜图结果表」，两者不互相顶替；留空的位置写明原因；HTML 预排版已渲染自查；质检清单逐项打勾且勾选结果已落盘。**推送草稿箱前已获用户确认。**

## 附：质检清单（交付前逐项打勾）

只装能验收的闸，不装应该早已发生的动作。「机制落点」「对事不对人」「故事有具体的人」这类设计属性在各阶段执行中保证，不在此重复。

- [ ] 数据口径：关键数字多源核实过，全部来自「可写事实清单」，文末有「数据口径说明」？
- [ ] 底稿：调研底稿已落盘（打分卡/双图/数据系列/立意产出清单＋拍板记录/四段对照表/深挖笔记/可写事实清单齐，章节对照 `references/draft-template.md` 无缺）？
- [ ] 概念界定：核心概念已界定且无歧义，全篇共用同一口径，读者不熟的词已给读者版解释、**且解释不晚于首次实质使用**（术语首现表已产出）？
- [ ] 引用：详细版正文每个关键数据有〔n〕，与文末来源一一对应？发布版由详细版压缩生成（非独立撰写），已去〔n〕，五类必留口径说明齐？
- [ ] 立意：经用户拍板，论点为带方向的陈述句，三测通过（证伪条件/反对者理由/可证判定齐）？
- [ ] 结构：主线经四段追问试讲定线（四段对照表+「断在哪」清单在手），骨架形态经一次呈报确认？**比喻**：⑧已判定用或不用，用了的过了"删掉它读者少理解什么"这道门槛？
- [ ] 单引擎：每节都能一句话答出「如何推进主线」？
- [ ] 成稿组织：每节说清一句、有硬料、能引出下一节，别每节一个模子，节间有推进接口？开头一屏内出现本文追问的问题且用的是全文最狠的落差？结尾未超出认知任务允许范围？第三步各项均附证据（无出处断言排查含各节核心句、事实→清单映射表、反对者版本归位表、可读性测试六项数据与清单均已产出）？
- [ ] 落差：所用落差均过当事人解释测试，反对者版本已进稿且在让步预算内（一处主场＋至多一处预告）？
- [ ] 时效：论据已标年份，过时素材已降级或反转进检验段？行情类数字已复核截止日期？
- [ ] 合规：两层扫描全过（极限词均有来源、无荐股表述），涉政题材的高危项为零，标题摘要无敏感词，角度级回避项与问题定性守住，置顶评论已备？
- [ ] 主观性：无来源的否定断言、情绪越位已清零？**机构主体无拟人化情绪描写**？
- [ ] 声明：开头有「基于公开报道整理」？
- [ ] 标题：**过可读性测试**（没读过正文的人能说出这篇讲什么事）？无公文腔？若用了比喻，它未成为唯一解码钥匙、且结尾接得住？
- [ ] 篇幅：在篇幅档内（**公众号后台口径：含标点、含引号，只去空白与 markdown 记号**；⑧第一步概算时已对齐）？超 5000 字已向用户说明理由？
- [ ] 数据系列：③⑥ 遇到的时间序列均已完整登记（注明出自哪份公报）？跨年份序列优先取自同一份公报；跨公报拼接的已查历史值是否被修订、以新版为准并标注？无一处用增速反推绝对值？
- [ ] 配图·图表：均过价值门槛（比文字更直观），数据来自可写事实清单（补全数据已标来源、反推值已标推算并与实测值区分线型），标题客观无观点，口径注脚齐全？
- [ ] 配图·图片：**「搜图结果表」已产出**（每个配图位一行：位置/渠道/检索词/候选数/最大尺寸/结果）——无表即视为未执行，**不得用配图·图表那一项的判定顶替**；表中每张选中图均来自官方素材或开放图库（无自媒体来源、无第三方水印），署名齐全，效果图已标「非实景」，过分辨率门槛（效果图 ≥1000px／新闻实景图 ≥800px）、横图、主体明确、非营销海报；留空的位置已写明原因？
- [ ] 交付：HTML 预排版渲染抽查正常，图表与图片已插入对应位置？若推送草稿箱，已先 `--dry-run` 自查、已获用户确认、且未做群发？
