# 城市镜像写作法

> 版本：v4.43（2026-08-20）。每次修订更新本行，变更明细见 `CHANGELOG.md`。
> 核心思想：以一个多年工作生活在太原的人的视角，从太原的热点话题出发——透过现象和情绪化的舆论，用资料收集去洞察事件背后的背景、决策机制与时空局限；再带着全国视野，为太原的事在全国找到类似情景，多侧面地对照解读。落点永远放在「机制差异」，而不是「城市高下」。文章是面向普通太原市民的深度文：逻辑、数据、案例对比都要完整，但表达要让市民看得懂，读完能多一层思考与共鸣，引发讨论。

## 读懂本 skill：约束三层制

本 skill 的规则分三层，效力不同，不要一视同仁：

- **红线（必守，无例外）**：来源纪律、核实与锁清单、可写事实清单、口径与暂缺、双层合规、情绪越位、单引擎检查、落差自检（当事人测试）、试讲纪律（必须难看、强制举证、不作成稿底稿）、调研底稿落盘、禁止用修辞补救上游问题；
- **默认（照跑，用户可一句话关掉）**：立意五步流程、篇幅分档、双审、标题参考、HTML 交付；
- **工具（帮你找，不替你写，找到即退役）**：④换问法的五段通用问法表（原骨架五问第 4 问已并入其中「解释段」一行；第 1/2/3/5 问 2026-08-07 经台账两篇未出力删除，原文存 CHANGELOG v2.3）、样式库（⑧定骨架形态时查 `references/pattern-samples.md`）。

规则的去留由实战审计决定（见末节），不由偏好决定。

## 全流程总览

```
① 概念界定（三类歧义）→ ② 选题评估（负面清单 → 客体 → 受众 → 写 / 不写）
③ 广撒网（双图）→ ④ 立意决策（五步）→ ⑤ 结构（四段追问试讲→按主线分节→单引擎）
→ ⑥ 沿线深挖 → ⑦ 核实锁清单 → ⑧ 叙事成稿（定表达 → 写 → 扫）
→ ⑨ 双审（合规+主观性）→ ⑩ 交付（MD 定稿 → HTML 预排版）
（改稿按「改稿复检」的分级规则回到 ⑨ 重跑）
```

每个阶段都有明确的产出物和质检标准，不要跳步。贯穿全程的五条骨干规则：

- **调研三轮**：③广撒网 → ⑥沿线深挖 → ⑦核实锁清单。三轮笔记全程继承——登记过的事实与来源，任何一轮不重复检索，上一轮作业是下一轮底稿；
- **用户拍板点**：②选题（多题待筛时；单题直接展示回避项后继续）、④立意、⑧骨架形态（⑧第一步末尾一次呈报确认；判定用比喻的，连比喻一并报）。不要替用户决定；
- **⑨双审**在发布前完成，两审缺一不可；
- **按需读取阶段文件**：见下方「阶段路由与接口总表」，只读当前命中的，不要一次全加载；
- **调研底稿落盘（红线）**：每轮产出都追加写进工作目录下的 `文章名_调研底稿.md`（普通 md 即可）——**登记在文件里，不只登记在上下文里**。要落盘的有七样：打分卡、双图、立意产出清单、各拍板点的用户选择记录、四段对照表、深挖笔记、可写事实清单。章节骨架见 `references/draft-template.md`，照模板留好空节，防漏（判例：台账第 2 篇）。（思想借自横纵分析法的研究底稿落盘，格式从简。）

### 关键术语一句话（只作地图，完整定义在各自首次出现处）

- **落差**：两组对不上的事实、两边都有出处——文章的燃料（②）；
- **打分卡**：选题评估的结构化产出：载体/落差/体量/时效/在地/回避项（②）；
- **双图**：认知地形图（别人写过什么）＋素材地图（事实本身有什么）（③）；
- **认知任务**：论点落在认知五段（描述/解释/检验/预测/规范）的哪一段——决定论证结构与结尾方式（④定名）；
- **主线**：读者跟着什么走——本 skill 只有一条「追问」，⑤按四段落地（抛问题／拆机制／摆证据／给方案）；**骨架形态**：追问时读者跟着对象／时间／空间／流转哪一种走、外地材料怎么进来（⑧定）；**修辞主线**：贯穿全篇的比喻（⑧第三步**条件触发**，只在有理解缺口时才用，多数文章不用）；
- **样式**：已验证的"主线×素材形态"组合——问题线索式／双线对照式／故事群像式／本地纵深式，⑧定骨架形态时作样文与篇幅档参考；
- **可写事实清单**：⑦锁清单的产出——成稿只准用清单内的事实；
- **台账**：`AUDIT.md` 里的逐篇实战审计记录，规则去留的证据来源。

## 改稿复检（多稿迭代）

改稿是常态，复检按幅度分级，不搞一刀切。**分级规则与各级动作见 `references/stages/09-review.md`**（结构性改动／段落级／字句微调／外部工具改稿四档）。其中一条要记住：**外部工具改稿（其他 AI、人工编辑）不论幅度，至少按段落级处理**——外来"润色"是敏感词回流的主要来源（实战验证）。

**完整清单见 `references/stages/09-review.md`**，交付前逐项打勾。只装能验收的闸，不装应该早已发生的动作。

## 实战审计（每篇成稿后必做）

写完一篇文章，回头盘点约束发力情况：哪些规则在这篇里真起了作用（写进文章里的证据），哪些没出力。连续两篇实战未出力的规则，进入降级候选——默认层降工具层、工具层删除，向用户报告后执行。规则的去留由实战证据决定，不由偏好决定。

- **台账**：审计结果逐篇追加写入 `AUDIT.md`（篇名＋各规则出力/未出力）——"连续两篇"以此台账为准，没有台账的降级不算数。版本变更记录在 `CHANGELOG.md`，两者分开：**改了什么看 CHANGELOG，规则有没有用看 AUDIT**；
- **豁免**：应急预案类规则（发布后补救顺序、评论区预判、`_已丢.md` 防重）价值在存在而非高频触发，不适用发力统计，不进降级候选。
